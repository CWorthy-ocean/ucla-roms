The CPP keys ``SALINITY`` and ``MPI_MASKING`` are now namelist settings in ``PARAM_SETTINGS``. A ``cppdefs.opt`` that defines one of them stops the build with an error that names its replacement; delete the line (an ``#undef`` line is harmless). Every ``cppdefs.opt`` made from the template defines ``SALINITY``, so every case must delete that line.

- ``SALINITY`` is ``salinity = .true.``, the default. A temperature-only case sets ``salinity = .false.``; it runs as a build without ``SALINITY`` did. A case's own ``ana_init.h``, ``ana_vmix.h`` or ``ana_frc_river.h`` that sets salinity under ``#ifdef SALINITY`` must use ``if (salinity)`` instead: the key is never defined now, so such a block would be skipped. ``Scoef`` and ``S0`` are always in ``LIN_RHO_EOS_SETTINGS`` (used only with salinity). ``salinity = .false.`` stops the run with ``sflx_corr``, or in a ``MARBL`` build (MARBL and the CDR outputs read salinity). Without salinity, the forcing output (``wrt_frc``) has no ``ssflx``.
- ``MPI_MASKING`` is ``mpi_masking = .true.`` (default ``.false.``). It still needs a ``PARALLEL_IO`` build, and stops the run otherwise.
- The ``CPPS`` attribute of output files no longer lists these keys.
