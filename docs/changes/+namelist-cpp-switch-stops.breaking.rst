ROMS now stops at start-up, with a message naming the switch and the CPP keys it needs, when ``do_cdr_output`` (``MARBL`` and ``MARBL_DIAGS``) or ``do_cdr_gas_exch_output`` (``MARBL``) is ``.true.`` but the build lacks those keys; before, the switch was silently ignored. Set the switch to ``.false.`` or define the keys in ``cppdefs.opt``.
- These groups are now read even when their CPP keys are off: a missing group is still fine, but an unknown or misspelled key in one now stops the run.
- ROMS also stops when ``calc_pflx = .true.`` and ``pflx_timescale`` <= 0, and on an unreadable ``REFERENCE_DATE_SETTINGS`` group (such as a misspelled key); a missing ``REFERENCE_DATE_SETTINGS`` group still means 2000-01-01.
