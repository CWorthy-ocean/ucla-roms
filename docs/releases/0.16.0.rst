0.16.0
------

Breaking Changes
~~~~~~~~~~~~~~~~

- With ``ANA_INITIAL``, ``inifile`` in ``INITIAL_CONDITIONS`` is now read, so a namelist that names a file that does not exist (such as the template's ``my_initial_conditions.nc``) stops at start-up: set ``inifile = ""`` to start from the analytical state. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)

Changes to Output
~~~~~~~~~~~~~~~~~

- Results of 3-D runs change, because the predictor step splits the vertical velocity differently into its explicit and implicit parts (see Bug Fixes). (`#468 <https://github.com/CWorthy-ocean/ucla-roms/pull/468>`_)

  - Where the vertical Courant number ``dt |W| / dz`` stays below about 0.7 the change is at rounding level; above it, mostly over steep topography and in strong vertical flows, more of the vertical advection in the predictor is implicit than before.

- Builds without ``PARALLEL_IO`` now write their output files (history, averages, restart and the other per-rank files) as classic CDF-5 instead of netCDF-4, as ``PARALLEL_IO`` builds already did, so that both write the same file format; the values in them are unchanged, including the fill values of cells a writer leaves unwritten (such as the boundary rows and columns of the momentum diagnostics). (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)

  - The per-rank files are no longer compressed, so they are larger: on the test suite's grids, which have little land, history and BGC files 1.3-1.4 times and restart files 1.1 times. On domains with much land the growth can be larger. Files joined by ``ncjoin`` are still compressed netCDF-4.
  - In the per-rank extraction files (``_ext``) every set's records now use the one ``time`` dimension instead of a ``time_<set>`` dimension per set (a CDF-5 file has one unlimited dimension), and ``ocean_time`` holds each record's time; ``extract_data_join`` joins them as before.

- The vertical velocity ``w`` in history, averages and extracted boundary output now includes the water added by point volume sources (pipes, and CDR releases with ``cdr_volume``), as ``omega`` already did, so ``w`` changes above such sources. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)
- Averaged ``u``, ``v``, ``temp``, ``salt`` and the passive, CDR and BGC tracers in ``_avg`` and ``_bgc_avg`` change: each record now averages the states at the ends of its window's steps, one step later than before. ``w`` changes slightly in ``_his``, ``_avg`` and extracted boundary data. (`#472 <https://github.com/CWorthy-ocean/ucla-roms/pull/472>`_)
- The ``_avg``, ``_bgc_avg`` and ``_bgc_dia_avg`` files have two new variables, ``avg_begin_time`` and ``avg_end_time`` (in seconds, like ``ocean_time``): the start and end of each record's averaging window, as in the ``_cdr``, ``_cdrgas`` and ``_uscl`` files. (`#472 <https://github.com/CWorthy-ocean/ucla-roms/pull/472>`_)

  - ``ocean_time`` is unchanged: the window end in ``_bgc_avg`` and ``_bgc_dia_avg``, and the mean of the times of the window's steps in ``_avg`` (half a step after the window's midpoint), so pair ``_avg`` and ``_bgc_avg`` records by ``avg_end_time``.

- Results change in every 3-D run with ``UV_VIS2`` and either a nonzero ``visc2`` or, with ``SPONGE``, a nonzero ``v_sponge`` (see Bug Fixes); runs without lateral viscosity are unchanged bit for bit. (`#473 <https://github.com/CWorthy-ocean/ucla-roms/pull/473>`_)

  - The change is largest in ``ubar``, ``vbar`` and ``zeta`` in the sponge layer next to open boundaries, which the sponge now damps.

New Features
~~~~~~~~~~~~

- ``pio_direct_read`` in ``PIO_SETTINGS`` (default ``'on'``): ``PARALLEL_IO`` runs read the grid file and the initial or restart file directly with O_DIRECT when they are classic netCDF (CDF-1, CDF-2, CDF-5), instead of through PIO; results are unchanged. (`#462 <https://github.com/CWorthy-ocean/ucla-roms/pull/462>`_)

  - On a Pacific MARBL run on 2 Derecho CPU nodes (measured on ``main``), reading the grid and the 118-GB restart takes 32 s instead of 75-78 s, and start-up drops from 117-121 s to 74 s.
  - ``'off'`` reads through PIO as before: use it on a file system that rejects or slows down O_DIRECT reads, or to rule them out while debugging. ``'verify'`` reads both ways, reports values that differ and runs on PIO's values. netCDF-4 files, forcing files and all output still go through PIO. Builds without ``PARALLEL_IO`` are unchanged.

Bug Fixes
~~~~~~~~~

- The split of the vertical velocity into an explicit and an implicit part (``omega``) is now sized for the predictor step that ``pre_step3d`` takes, ``(1 - AM3_crv) dt`` = 5/6 ``dt``, instead of ``0.6 dt``, so the explicit part's Courant number in the predictor stays within its limit of 1; before, it could reach about 1.4. (`#468 <https://github.com/CWorthy-ocean/ucla-roms/pull/468>`_)

  - The same fix as upstream CESR-lab/ucla-roms commit 9684929 ("omega: Fix the implicit/explicit W split").
  - ``AM3_crv`` is now defined once, in ``scalars``, and both ``pre_step3d`` and ``omega`` read it.

- The CDR forcing file (``cdr_file``) is now found when ``frcfiles`` in ``FORCING_FILES`` is empty. Before, such a run stopped because ``cdr_volume`` (or another CDR variable) was not found, unless the CDR file was also listed in ``frcfiles``. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)
- The normalization of parameterized CDR releases spread over several cells (``cdr_hsc`` > 0) no longer depends on the tiling (``NP_XI``, ``NP_ETA``): it was a sum of per-rank partial sums, whose rounding depended on the tiling. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)

  - With ``BUILD_MODE=strict`` or ``BUILD_MODE=test``, runs with such releases now give the same results to the last bit with any tiling. The default optimized build has other tiling-dependent rounding, with or without CDR releases, but its release weights are the same in every tiling.
  - Results of runs with such releases can change at the rounding level.

- Parameterized and depth-profile CDR releases (``cdr_forcing_parameterized``, ``cdr_forcing_depth_profiles``) now stop at start-up with a message in a build without ``SPHERICAL``, instead of crashing: they are placed by ``cdr_lon`` and ``cdr_lat``, which needs the grid's longitude and latitude. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)
- With ``ANA_INITIAL``, a file named by ``inifile`` in ``INITIAL_CONDITIONS`` is now read over the analytical initial state, so an analytical case can be restarted from its restart file. Before, the group was never read, and such a restart silently started again from the analytical state. (`#470 <https://github.com/CWorthy-ocean/ucla-roms/pull/470>`_)

  - Leave ``inifile`` empty, or leave the group out, to start from the analytical state.

- The averages (``_avg``, ``_bgc_avg``) add ``u``, ``v`` and the tracers as they are at the end of each step, as the history files write them; they used to add the state of the step before, so each record averaged its window shifted back by one step. (`#472 <https://github.com/CWorthy-ocean/ucla-roms/pull/472>`_)

  - ``w`` (history, averages and extracted data) took ``u`` and ``v`` of the step before with the depths of the end of the step; it now takes both at the end of the step.

- Lateral viscosity (``UV_VIS2``, including the sponge viscosity ``v_sponge``) now acts on the depth-averaged flow: ``visc3d`` added its depth-integrated term to the barotropic forcing ``rufrc``/``rvfrc`` without multiplying it by the cell area, so ``ubar`` and ``zeta`` received the viscous term divided by the cell area in square metres (1e5 to 1e8 at typical resolutions), and the sponge damped only the depth-varying flow. (`#473 <https://github.com/CWorthy-ocean/ucla-roms/pull/473>`_)

  - The same fix as upstream CESR-lab/ucla-roms commit 3db2036f ("Bug fix to horizontal viscosity").

Improvements
~~~~~~~~~~~~

- ROMS now reads the time axes of classic-format (CDF-1, CDF-2, CDF-5) forcing files in 8-KiB blocks instead of one file-system block (4 MiB on Lustre) per time value, at start-up and whenever a run reaches a new forcing file, so finding forcing records no longer reads gigabytes; results are unchanged. (`#460 <https://github.com/CWorthy-ocean/ucla-roms/pull/460>`_)

  - On a Pacific MARBL run on 2 nodes from a cold cache, the forcing search before the first record drops from 29-36 s to 7-8 s.
